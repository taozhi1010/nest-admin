## 版本详情

### v1.2.0

**发布日期**：2026-11-17　**Git 标签**：`v1.2.0`

文件管理功能、上传与安全加固、CI 质检门禁的一次集中更新。

#### 新增

- 内容管理新增文件管理页：图片预览、排序、扩展名筛选与时间范围搜索，支持批量删除；后端配套列表/扩展名枚举/删除接口
- 部署流水线新增 `quality-gate` 质检门禁（frozen-lockfile 安装 + `tsc --noEmit` + 单元测试），部署 job 通过 `needs` 强制先过门禁；CI actions 全部钉版本（checkout v5、ssh-action v1.2.4）
- config 启动校验（joi）：`JWT_SECRETKEY` 全环境必填非空，缺失直接拒绝启动；`NODE_ENV=test` 配置映射补齐
- 上传链路加固：Multer `limits.fileSize` 10MB（单传/分片/头像三处）、扩展名白名单（可在 yml 配置 `allowedExts` 覆盖）、静态资源对非位图文件强制 `Content-Disposition: attachment`
- 参数缓存统一 10 分钟 TTL；软删参数读取过滤、参数删除/重命名时同步失效缓存

#### 变更

- 样式清理：删除 `btn.scss`、`element-ui.scss`，解散 `ruoyi.scss`，清除 vue-element-admin 遗留演示样式与死类
- 手动事件监听四处统一改为 `useEventListener`（TagsView / SearchModal / TopNav / ScrollPane），分页回顶改为原生 `scrollTo` smooth
- 分片合并的对象 key 由硬编码 `test` 前缀改为 `serveRoot` 配置

#### 修复

- 文件页批量删除按钮误传 MouseEvent 导致确认后报错；顺带补列表竞态守卫与扩展名请求兜底
- 密码哈希泄漏补齐收口：`/system/user/profile`、用户详情、角色分配/取消分配列表四处响应层剥离 `password`（会话快照与修改密码校验不受影响）
- 用户状态切换/详情/会话信息空结果统一返回 400「用户不存在」，软删用户持有效凭证登录不再报错
- 登录日志、操作日志写入失败不再产生未处理 Promise 异常，仅告警不影响主流程

#### 升级注意

- **上传行为变化**：`.svg`、`.html` 等白名单外扩展名被拒绝（防存储型 XSS），如需放开在 yml 配置 `allowedExts`
- 非位图静态资源响应带 `Content-Disposition: attachment`，浏览器不再内联预览
- 本地 `dist/main.js` 直启必须提供 `JWT_SECRETKEY` 环境变量或设置 `NODE_ENV=development`，否则拒绝启动（fail fast，属设计）
- 用户相关接口响应不再包含 `password` 字段

### v1.1.0

**发布日期**：2026-11-15　**Git 标签**：`v1.1.0`

注册体系、安全加固与前端工程化的一次集中更新。

#### 新增

- 注册体系：邮箱/图片验证码双模式、账号实时查重、密码强度校验与防刷限流；登录验证码按账号失败次数动态启用
- 文章与专栏支持游客访问
- 部署链路支持可选的邮件 SMTP 配置（`MAIL_*`，未配置时自动关闭）
- 前端引入 `useCrud` 与 `DictTag` 统一列表页，接入 Prettier / ESLint / husky

#### 变更

- 后端认证流程归拢到 `system/auth`，用户服务拆分出 Excel 模块；移除代码生成功能
- Element Plus 改为按需引入；登录逻辑抽为 `useLogin`，「记住密码」降级为「记住用户名」
- 升级 Node 22、`@vueuse/core` 15，Dockerfile 固定 pnpm 版本

#### 修复

- 安全：LIKE 查询全量参数绑定、排序列白名单校验、上传文件名消毒、用户信息脱敏
- 稳定性：bcrypt 异步化、Redis 配置加固、会话即时失效、多表写入事务化、用户名唯一索引
- 部署与前端：修复镜像构建假成功、RustFS 凭据兜底、登录 loading、登出清理、列表重置等

#### 升级注意

- 邮件配置可选；不配置 `MAIL_*` 时注册继续使用图片验证码
- Element Plus 已按需引入，自定义全局图标需显式引入
- `sys_user.user_name` 新增唯一索引，升级前先清理重复账号
- 构建环境需 Node ≥ 22，pnpm 版本与 Dockerfile 保持一致
- 代码生成模块已移除

### v1.0.1

**发布日期**：2026-10-25　**Git 标签**：`v1.0.1`

文档站接入开发环境，部署流水线改为由 `master` 触发。

#### 新增

- 文档站支持中英文标题切换，只切换导航、侧边栏和页面标题，正文保持中文
- 新增「发布记录」页，侧边栏以时间线形式展示历史版本
- 开发环境通过前端 8888 的 `/manual/` 访问文档，首页新增「项目文档」入口
- `bin/dev.sh` 同时启动文档服务，并在启动前释放 5173 端口

#### 变更

- 部署工作流触发分支由 `feature-1.0` 改为 `master`

#### 修复

- 文档服务就绪探测改用 `localhost`，避免 VitePress 仅监听 IPv6 时误报未就绪

#### 升级注意

- 「项目文档」入口仅在开发环境显示；生产环境需先发布文档产物并在 nginx 配置 `/manual` 路由

### v1.0.0

**发布日期**：2026-10-25　**Git 标签**：`v1.0.0`

首个部署版本，master 与 dev 对齐。

#### 新增

- 数据字典改为前端本地持久化缓存，并通过服务端版本号校验缓存是否过期，减少重复请求
- 新增本地一键启动脚本 `bin/dev.sh`，配套端口释放脚本 `scripts/free-port.mjs`
- 补充部署基建：GitHub Actions 与 `.workflow` 分支流水线
- 补充在线部署、自动部署与协作开发文档

#### 变更

- 后端字典缓存合并为单 key（`sys_dict:all`），减少 Redis key 数量
- 合并字典相关 composable，精简 store 结构
- 统一以 `feature-1.0` 作为上游唯一主线

#### 修复

- 修复字典查询中 LIKE 通配符未转义导致的注入风险
- 验证码改为按字符串比较，修复登录总是失败的问题
- 后端增加断线自愈，避免瞬时连接错误导致进程退出
- 修复静态图片路径被错误拼接 API 前缀
- 修复 404 页面 HTML 标签未闭合
- 为 Redoc 补充 CSP 指令并关闭 telemetry

#### 升级注意

- 字典缓存 key 变为 `sys_dict:all`，升级后建议清空旧的 `sys_dict:*` 缓存
- 前端缓存带 schema 版本号；字典结构有调整时，需要同步递增 `CACHE_SCHEMA_VERSION` 以触发刷新
- 仓库不再跟踪密钥与本地产物，部署时需自行提供 `.env` 等配置

## 新增一条发布记录

1. 确认 `master` 已合并完成，打标签并推送：

   ```bash
   git tag -a v1.1.0 -m "v1.1.0: <一句话概括>"
   git push origin v1.1.0
   ```

2. 在「版本一览」表格顶部新增一行。
3. 在 `.vitepress/config.mts` 的 `/releases` 侧边栏 `items` 顶部新增一条时间线记录：

   ```ts
   { text: 'v1.1.0 · YYYY-MM-DD', link: '/releases#v1-1-0' },
   ```

   锚点由版本号生成，`.` 会变成 `-`，例如 `v1.1.0` 对应 `#v1-1-0`。

4. 复制下面的模板，放到「版本详情」的最上方并填写内容，没有的小节可以删除。

```md
### v1.1.0

**发布日期**：YYYY-MM-DD　**Git 标签**：`v1.1.0`

#### 新增

-

#### 变更

-

#### 修复

-

#### 升级注意

-
```
