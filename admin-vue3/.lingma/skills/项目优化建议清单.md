## 一、代码质量与规范

### 1.1 混合使用 JS 和 TS ⚠️ 高优先级

**现状：**
- 项目同时存在 `.js` 和 `.ts` 文件
- Composables 已迁移到 TypeScript（11个文件）
- Utils、API、Store、Views 等仍大量使用 JavaScript
- `tsconfig.json` 中 `"allowJs": false`，但实际存在大量 JS 文件

**问题：**
- 类型系统不完整，无法享受 TypeScript 的全部优势
- 开发体验不一致，部分文件有类型提示，部分没有
- 重构和维护成本增加

**建议：**
```markdown
✅ 逐步将所有 .js 文件迁移到 .ts/.tsx
✅ 优先迁移高频修改的核心模块：
   - src/utils/*.js → src/utils/*.ts
   - src/api/**/*.js → src/api/**/*.ts
   - src/store/modules/*.js → src/store/modules/*.ts
   - src/views/**/*.vue 的 <script> 改为 <script lang="ts">
✅ 更新 tsconfig.json: "allowJs": true（过渡期）
✅ 建立迁移规范和检查清单
```

**影响范围：** 全项目  
**工作量估计：** 大（需分阶段进行）  
**收益：** 高（类型安全、开发效率、可维护性）

### 1.2 Console 语句未清理 ⚠️ 中优先级

**现状：**
发现 46+ 处 console 语句，包括：
- `console.log` - 调试信息（约 10 处）
- `console.warn` - 警告信息（约 5 处）
- `console.error` - 错误信息（约 31 处）

**主要分布：**
```typescript
// src/views/system/user/ - 用户管理模块（最多）
console.error('查询部门树失败:', e)
console.log('导入接口返回数据:', response)

// src/views/game/article/ - 游戏文章模块
console.log(sys_article_status, '数据字典')

// src/composables/ - 组合式函数
console.warn(`[${s_url}]: ${message}`)  // useRequest.ts
console.error('[字典] 加载失败:', error)  // dict store

// src/store/modules/dict.ts - 字典状态管理
console.log('[字典] 全量加载完成，已缓存', this.dict.length, '个字典类型')
```

**说明：**
- 大部分 console.error 用于错误追踪，应保留
- console.log 多为调试代码，生产环境应移除
- console.warn 用于重要警告，可考虑保留

**建议：**
```markdown
✅ 引入 eslint-plugin-no-console 或在现有配置中启用
✅ 生产环境自动移除 console（vite.config.ts 已配置 esbuild minify）
✅ 分类处理：
   - 保留必要的 console.error 用于错误追踪（31处）
   - 移除所有 console.log 调试代码（10处）
   - 评估 console.warn 是否需要保留（5处）
✅ 使用统一的日志工具替代 console（如 useMessage 或自定义 logger）
✅ 添加环境变量控制日志输出：VITE_ENABLE_LOGS
✅ 优先清理 views 目录下的调试代码
```

**配置文件示例：**
```typescript
// vite.config.ts
export default defineConfig({
  build: {
    minify: 'esbuild',
    esbuildOptions: {
      drop: ['console', 'debugger'] // 生产环境移除 console 和 debugger
    }
  }
})

// 或者更精细的控制（仅移除 log 和 debug，保留 warn 和 error）
esbuildOptions: {
  pure: ['console.log', 'console.debug']
}
```

**影响范围：** 所有视图和组件  
**工作量估计：** 小  
**收益：** 中（代码整洁度、生产环境性能）

**改进情况：**

```markdown
✅ 为 Store state 定义接口

```

**改进示例：**
```typescript
// 定义字典项类型
interface DictItem {
  label: string
  value: string | number
  elTagType?: string
  [key: string]: any
}

// 改进 useDict
const getDictLabel = (type: string, value: number | string | undefined | null): string | number | undefined | null => {
  if (value === undefined || value === null) return value
  const dict: DictItem[] = dictStore.getDict(type)
  if (!dict) return value
  
  const item = dict.find((item) => item.value == value)
  return item ? item.label : value
}
```

**工作量估计：** 中

### 2.3 Vue 组件缺少类型标注 ⚠️ 中优先级

**现状：**
- 大部分 `.vue` 文件使用 `<script setup>` 但未指定 `lang="ts"`
- Props 和 Emits 未使用 TypeScript 定义
- Ref 和 Reactive 缺少类型注解

**建议：**
```markdown
✅ 所有 Vue 组件使用 <script setup lang="ts">
✅ 使用 defineProps<Type>() 泛型语法
✅ 使用 defineEmits<{...}>() 泛型语法
✅ 为 ref/reactive 添加类型注解
✅ 使用 withDefaults 设置默认值
```

**改进示例：**
```vue
<script setup lang="ts">
interface Props {
  src: string
  width?: number | string
  height?: number | string
}

const props = withDefaults(defineProps<Props>(), {
  src: '',
  width: '',
  height: ''
})

const realSrc = computed(() => {
  if (!props.src) return
  let real_src = props.src.split(',')[0]
  return getImageUrl(real_src)
})
</script>
```

**影响范围：** 所有 Vue 组件
